# آسيا — نظام إدارة المعاملات والخزينة والمستندات

Next.js 15 (App Router) + TypeScript + Tailwind v4 + Supabase. واجهة عربية RTL، PWA قابلة للتثبيت.

## 1) قاعدة البيانات (Supabase)
1. أنشئ مشروعاً في Supabase.
2. من **SQL Editor** شغّل بالترتيب: `supabase/migrations/0001_schema.sql` ثم `0002_app_support.sql` ثم `0003_seed_service_templates.sql` ثم `0004_reports_and_safeguards.sql` ثم `0005_trash_restore.sql` ثم `0006_cheque_method.sql` ثم `0007_payment_details.sql`.
3. من **Authentication > Users** أنشئ أول مستخدم (بريد وكلمة مرور). **أول مستخدم يُسجَّل يصبح صاحب العمل تلقائياً.** بعدها أضف الموظفين من التطبيق: الإعدادات > الموظفون.
4. من **Authentication > Providers > Email** عطّل "Allow new users to sign up" حتى لا يسجل أحد من الخارج.

## 2) التشغيل محلياً
```powershell
copy .env.example .env.local   # ثم املأ القيم
npm run vapid                  # يولّد مفاتيح الإشعارات (ضعها في .env.local)
npm run dev
```

## 3) المتغيرات
| المتغير | الاستخدام |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` | من Project Settings > API |
| `SUPABASE_SERVICE_ROLE_KEY` | خادم فقط: الروابط الموقعة، صفحة المشاركة، إنشاء المستخدمين، فحص التنبيهات |
| `NEXT_PUBLIC_SITE_URL` | عنوان الموقع الحقيقي (يُبنى عليه رابط المشاركة) |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` / `VAPID_SUBJECT` | إشعارات الهاتف والكمبيوتر (لصاحب العمل فقط) |
| `CRON_SECRET` | سر طويل عشوائي، يحمي `/api/cron/alerts` ويوقّع كوكي رمز المشاركة |

## 4) النشر على Railway
1. ارفع المشروع إلى GitHub ثم New Project > Deploy from GitHub.
2. أضف المتغيرات أعلاه في Variables (و`NEXT_PUBLIC_SITE_URL` = رابط Railway أو دومينك).
3. الأمران الافتراضيان يكفيان: `npm run build` ثم `npm run start`.
4. **فحص التنبيهات اليومي يعمل داخل التطبيق نفسه** (يفحص كل 3 ساعات بين 7 صباحاً و8 مساءً بتوقيت الإمارات). ويمكن استدعاؤه يدوياً: `POST /api/cron/alerts` مع `Authorization: Bearer <CRON_SECRET>`.
5. بعد النشر: افتح التطبيق > الإعدادات > إشعاراتي > فعّل الإشعارات على جهازك. على الآيفون ثبّت التطبيق أولاً (مشاركة > إضافة إلى الشاشة الرئيسية).

## 5) ملاحظات أمنية
- ملفات العملاء في Bucket خاص `vault`، ولا يُقرأ أي ملف إلا عبر رابط موقّع قصير العمر يولده الخادم (120 ثانية، و60 ثانية لروابط المشاركة).
- الأرصدة وحركات الخزينة والتقارير محمية بسياسات RLS حسب الصلاحية، لا بإخفاء الواجهة فقط.
- روابط المشاركة تُخزَّن مجزّأة (SHA-256)، ويظهر الرابط الكامل مرة واحدة عند الإنشاء. الرمز السري يُقفل بعد 5 محاولات خاطئة.
- الفاتورة والإيصال: صفحة طباعة رسمية، "حفظ كـ PDF" من نافذة الطباعة (يحفظ العربية بدقة كاملة).

## 6) الميزات الأساسية
- **البحث بالكتابة أو الصوت** (`/search` أو Ctrl+K ثم «بحث متقدم»): كتابة أو صوت بالعربية، يفهم الأسماء والحالات والمستحقات وأنواع المستندات والفترات والمبالغ، ويجيب على أسئلة مثل «رصيد الكاش» و«عملاء عليهم مستحقات». البحث الصوتي يعمل على Chrome وSafari (يتطلب HTTPS).
- **المستندات** (`/documents`): مكتبة كل الملفات مع تقسيم حسب العميل أو النوع، وفلاتر الحالة، ورفع متعدد وكاميرا.
- **الحسابات الدقيقة**: الأرصدة تُحسب من دفتر الحركات فقط. لا يُسمح بدفعة أكبر من المتبقي، ولا بسحب كاش أكبر من الرصيد، والتحويل الداخلي لا يُحتسب إيراداً ولا مصروفاً، والجرد يسجل الفرق.
- **التقارير** (`/reports`): وارد، رسوم حكومية، مصاريف، صافي الكاش، أتعاب مفوترة، أداء الموظفين، أعلى العملاء، أعمار الديون. و**كشف حساب** للخزينة (برصيد جارٍ) ولكل عميل، قابل للطباعة.
- **نسخة احتياطية**: الإعدادات > المكتب والفواتير (للمالك).

## 7) ربط الموقع لاحقاً (assia.ae)
أبسط ربط بلا برمجة: أضف في الموقع زر «دخول الموظفين» يفتح رابط التطبيق. لاحقاً يمكن إضافة نموذج «طلب خدمة» في الموقع يُنشئ معاملة جديدة في التطبيق عبر نقطة API محمية بمفتاح.

## 8) سهولة الاستخدام
- **حجم الخط** (صغير / متوسط / كبير) و**الوضع الداكن / الفاتح / التلقائي**: أزرار في أعلى كل صفحة، ويُحفظ الاختيار على كل جهاز.
- أزرار كبيرة للإجراءات اليومية في الصفحة الرئيسية، وصفحة **المساعدة** بخطوات مبسطة لكل مهمة.
- **سلة المحذوفات**: الحذف لا يمحو شيئاً، ويمكن الاسترجاع من الإعدادات.

## 9) تتبّع المعاملات والدفعات
- لكل معاملة: من سجّلها ومتى، ومن المسؤول عن متابعتها، ومرحلتها (جديدة ثم قيد الإجراء ثم مكتملة)، وحالة الدفع (غير مدفوعة / جزئياً / بالكامل).
- لكل دفعة: التاريخ الحقيقي، وطريقة الدفع (كاش، بطاقة، تحويل بنكي، شيك)، ورقم الحوالة أو الشيك، واسم المحوِّل، وصورة الإيصال المرفقة، ومن سجّلها.
- **سجل المعاملة**: كل تغيير (حالة، دفعة، مستند) مع اسم الموظف ووقته، ويراه كل موظف على معاملاته.
- **جرد الصندوق**: جدول بكل عمليات الجرد (النظام مقابل الفعلي والفرق ومن أجراه).

## 10) تجربة التطبيق بدون أي حساب (وضع تجريبي)
```powershell
npm install
npm run demo
```
ثم افتح http://localhost:3000. يعمل بقاعدة بيانات محلية داخل جهازك ببيانات عربية وهمية (عملاء، معاملات، دفعات، مستندات، خزينة). من الشريط البرتقالي في أعلى الصفحة يمكنك مشاهدة التطبيق كصاحب عمل أو مدير أو موظف. التغييرات تُحفظ محلياً، و`npm run demo:reset` يعيد البيانات الأصلية. رفع الملفات وتغيير كلمات المرور غير متاحين في هذا الوضع.

## 11) الفواتير وعروض الأسعار والخدمات
- **الفاتورة** بتصميم المكتب (الموجة، الشعار، الختم، الشريط السفلي) بثلاث لغات: عربي + English، أو العربية، أو English. تأخذ رقماً رسمياً تلقائياً عند أول فتح (يُضبط الرقم القادم من الإعدادات)، وتعرض بيانات التحويل البنكي إن بقي مبلغ غير مسدد.
- **عروض الأسعار** (`/quotes`) بنفس التصميم: لعميل أو لشخص جديد، ثم «وافق العميل، حوّل إلى معاملة» ليُنشأ كل شيء تلقائياً (العميل والبنود والأسعار).
- **الخدمات والأسعار** (`/services`): قائمة بأسماء عربية وإنجليزية وأسعار. عند إنشاء معاملة أو عرض تختار الخدمة فتمتلئ الأسعار، أو تكتب بنداً يدوياً.
- بيانات البنك والتواصل ورقم الفاتورة: الإعدادات > بيانات المكتب. شغّل `0008_items_quotes_invoices.sql`.

## 12) تخزين الملفات مجاناً (أكثر من 10 جيجا)
افتراضياً تُحفظ الملفات في Supabase (1 جيجا مجاناً). لسعة أكبر مجاناً استخدم مخزناً متوافقاً مع S3 وأضف 4 متغيرات في Railway، دون أي تغيير في الكود:

| المتغير | القيمة |
|---|---|
| `S3_ENDPOINT` | رابط الخدمة (R2: `https://<account>.r2.cloudflarestorage.com`) |
| `S3_BUCKET` | اسم الـ Bucket |
| `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` | مفتاحا الوصول |
| `S3_REGION` | `auto` (لـ R2)، أو منطقة B2 مثل `us-west-004` |

**Cloudflare R2 (10 جيجا مجاناً شهرياً، بلا رسوم تنزيل):** أنشئ Bucket خاصاً، ثم R2 > Manage API Tokens وأنشئ مفتاحاً بصلاحية Object Read & Write. ثم في إعدادات الـ Bucket أضف **CORS**:
```json
[{"AllowedOrigins":["https://app.assia.ae"],"AllowedMethods":["PUT"],"AllowedHeaders":["*"],"MaxAgeSeconds":3600}]
```
الملفات تبقى خاصة دائماً، ولا تُفتح إلا بروابط مؤقتة يصنعها الخادم. الملفات المرفوعة سابقاً في Supabase تبقى هناك ولا تُنقل تلقائياً.

## 13) دخول الموظفين برابط واحد (بدون بريد أو كلمة مرور)
1. شغّل `0009_office_entry_link.sql` في Supabase.
2. المالك: الإعدادات > الموظفون > **إنشاء رابط الدخول**، ثم **مشاركة في واتساب** وثبّته في مجموعة الموظفين.
3. الموظف يفتح الرابط، يضغط اسمه، وفي أول مرة يختار رمزاً من 4 إلى 6 أرقام. بعدها يبقى جهازه مسجّلاً دائماً، ويكتب الرمز فقط عند الدخول من جهاز جديد.
4. إضافة موظف: الاسم والهاتف فقط (بلا بريد). المالك والمدير يدخلان من صفحة تسجيل الدخول العادية.
5. **أمان:** 5 محاولات خاطئة تُوقف الدخول 15 دقيقة. «إعادة الرمز» لمن نسي رمزه، و«إنهاء الجلسات» عند ضياع الجوال، و«رابط جديد» إن تسرّب الرابط خارج المجموعة، و«إيقاف الرابط» مؤقتاً.

## 14) إدارة المستخدمين بالكامل (من عندك)
- الإعدادات > **المستخدمون**: أضف مستخدماً (الاسم، **المسمى بنص حر**، الهاتف، ونموذج صلاحيات للبداية)، واضغط اسم أي شخص لتعدّل كل شيء عنه.
- في صفحة الشخص: بياناته، وحالته (يعمل / موقوف)، وملاحظاتك الخاصة، وآخر دخول، و**صلاحياته واحدة واحدة** (ضع علامة أو أزلها)، ونسيان الرمز، وإنهاء الجلسات عند ضياع الجوال، وتغيير كلمة المرور، والحذف.
- الحذف: إن كان للشخص سجلات (معاملات أو دفعات) يُؤرشف بدل الحذف النهائي حتى يبقى التاريخ سليماً، ويمكن استرجاعه من قسم «المؤرشفون».
- لا توجد مسميات ثابتة (مالك/مدير/موظف) في الواجهة، وإنما يظهر المسمى الذي تكتبه. شغّل `0010_user_control.sql` في Supabase.

## 15) تشغيل كل شيء على Railway بدون Supabase
بدل Supabase يمكن أن تكون القاعدة PostgreSQL من Railway نفسه. الإعداد:
1. في مشروعك على Railway: **New > Database > Add PostgreSQL**.
2. في خدمة التطبيق > **Variables** أضف:

| المتغير | القيمة |
|---|---|
| `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` (مرجع جاهز لقاعدة Railway، اختره من القائمة) |
| `OWNER_EMAIL` | بريدك، مثل `assia_ae@yahoo.com` |
| `OWNER_PASSWORD` | كلمة مرورك (8 أحرف فأكثر) |
| `OWNER_NAME` | اسمك (اختياري) |
| `NEXT_PUBLIC_SITE_URL` | `https://app.assia.ae` |
| `CRON_SECRET` | نص عشوائي طويل |
| `S3_ENDPOINT` / `S3_BUCKET` / `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` / `S3_REGION` | مخزن الملفات (Cloudflare R2). **مطلوب** في هذا الوضع |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` / `VAPID_SUBJECT` | الإشعارات |

3. **لا تضع** أي متغير يخص Supabase، ولا `DEMO_MODE`.
4. عند كل تشغيل ينفّذ التطبيق `scripts/db-setup.mjs` تلقائياً: ينشئ الجداول، ويطبّق أي تحديث جديد من `supabase/migrations`، وينشئ حساب المالك في أول مرة. لا تشغّل ملفات SQL يدوياً.
5. ادخل بـ `OWNER_EMAIL` و`OWNER_PASSWORD`، ثم احذف `OWNER_PASSWORD` من المتغيرات (لا حاجة له بعد إنشاء الحساب).
6. الدخول: المالك بالبريد وكلمة المرور، والموظفون برابط المكتب والرمز، كما هو. تُحفظ الجلسات في قاعدتك وتبقى مفتوحة 400 يوماً على كل جهاز.
7. النسخ الاحتياطي: فعّل Backups لقاعدة Railway من إعدادات الخدمة إن توفرت في خطتك، وحمّل النسخة الاحتياطية الأسبوعية من الإعدادات.

## 16) متابعة الأخطاء (السجل)
- كل خطأ في أي إجراء يُكتب في **Railway > Deploy Logs** بوسم `[action-error]`، وأخطاء المتصفح (فشل رفع، انهيار صفحة) بوسم `[client-error]` مع اسم المستخدم.
- **فحص التخزين:** الإعدادات > بيانات المكتب > «فحص إعدادات التخزين». يكتب ويقرأ ويحذف ملفاً تجريبياً ويعرض أي خطأ بالاسم (مفتاح خاطئ، Bucket خاطئ، صلاحية ناقصة). وإن نجح الفحص وفشل الرفع من المتصفح فالسبب قاعدة **CORS** في Cloudflare.

## 17) فئات العملاء
العميل إما **فرد** أو **شركة** أو **كفيل**، ويظهر ذلك في تبويبات العملاء وفي المستندات (تقسيم وفلترة حسب الفئة). شغّل `0011_client_sponsor.sql` (يُطبَّق تلقائياً في وضع Railway).

## 18) التاريخ
كل حقول التاريخ تُكتب وتُعرض بصيغة **يوم/شهر/سنة** (الشهر في الوسط) مهما كانت لغة الجهاز: اكتب 8 أرقام (25112026) فتتحول إلى 25/11/2026، أو اضغط أيقونة التقويم.

الرابط الآن مثل `https://app.assia.ae/e/k7m2x9qa` (8 أحرف). الروابط الطويلة القديمة تبقى تعمل حتى تضغط «رابط جديد».

## 20) مرونة المستندات وملفات الشركات
- **نوع مخصص:** عند رفع أو تعديل مستند اختر «＋ نوع آخر» واكتب اسمه؛ يُحفظ ويظهر في القائمة بعدها.
- **تعديل المستند:** الاسم، النوع، تاريخ الإصدار والانتهاء، المجلد، التصنيف، والمعاملة المرتبطة.
- **نقل المستندات:** زر النقل على أي مستند، أو حدّد عدة مستندات (أو مجلداً كاملاً) من ملف العميل وانقلها إلى عميل أو شركة أو موظف، مع نسخها القديمة، وبربطها بمعاملة اختيارياً.
- **موظفو الشركة:** في نموذج العميل اختر «يتبع شركة». ملف الشركة فيه بطاقة «موظفو الشركة» ولكل موظف مجلد مستندات خاص. وفي المستندات يمكن التقسيم «حسب الشركة مع موظفيها».
- **رفع ملفاتك الحالية:** المستندات > «رفع مجلد كامل». اختر مجلداً من جهازك فتُرفع ملفاته بنفس ترتيب مجلداته، إما لعميل واحد أو بمجلد لكل عميل (يُنشأ العميل تلقائياً)، مع **تصنيف** (مكان أو جهة) تضعه على الدفعة، ونوع تلقائي من اسم الملف أو المجلد. الرفع 4 ملفات معاً مع شريط تقدم وإعادة محاولة الفاشل.
- **الصلاحيات:** تحت كل صلاحية شرح لما تسمح به، وفي قائمة المستخدمين ملخص لما يستطيع كل شخص فعله. شغّل `0012_documents_flex.sql` (يُطبَّق تلقائياً في وضع Railway).
